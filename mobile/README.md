# 📱 AgroGrowth Native Mobile Application

> **تطبيق AgroGrowth الفلاحي الذكي للهواتف المحمولة (Android & iOS)**  
> مبني باستخدام **React Native** و **Expo SDK 58** بالاعتماد الكامل على بنية Express API و Supabase ونماذج الذكاء الاصطناعي الزراعية التونسية.

---

## 🌟 رؤية المنتج والتجربة المحمولة (Mobile-First UX)

تم تصميم هذا التطبيق ليكون رفيقاً يومياً عملياً وسهل الاستخدام للفلاحين والمهندسين الزراعيين في الحقل:
1. **أولوية البساطة والوضوح:** أزرار كبيرة وعريضة (Touch Targets ≥ 48dp)، خطوط عربية واضحة، بدون مصطلحات معقدة.
2. **الواجهة العربية أولاً مع دعم RTL كامل:** ودعم التبديل الفوري للغتين الفرنسية والإنجليزية.
3. **أقل عدد من الخطوات:** إجراء الفحوصات والتشخيصات بنقرة واحدة (1-Tap Quick Actions).
4. **الشفافية في مصدر البيانات (Honest Data Provenance):** يوضح التطبيق للمستخدم ما إذا كان التحليل صادراً عن فحص حي، أم نموذج رؤية حاسوبية، أم دليل إرشادي زراعي معتمد.
5. **العمل في وضع عدم الاتصال (Offline Support):** تخزين مؤقت للطقس والمهام والحقول لتصفحها في المناطق الريفية ضعيفة التغطية. ذاكرة التخزين المؤقت **مُقسّمة لكل مستخدم** (بمعرّف المستخدم) وتُفرَّغ عند تسجيل الخروج، فلا يمكن لحساب أن يقرأ سجلات حساب آخر الخاصة على نفس الجهاز.

## 🧭 البنية والتنقل الرئيسي (Bottom Navigation)

1. **الرئيسية (Home):**
   - تحية مخصصة بحسب اسم الفلاح وولايته (تونس، باجة، القيروان، سوسة، صفاقس، قبلي...).
   - بطاقة حالة الطقس المباشرة من محطات الرصد الجوي (درجة الحرارة، الرطوبة، هطول الأمطار بالملّيمتر، سرعة الرياح، والنصيحة الزراعية لليوم). لا تُعرض «نسبة فرصة الأمطار» لأن مزوّد الطقس لا يوفرها.
   - إجراءات سريعة بنقرة واحدة:
     - 📸 فحص النباتات بالصورة (كشف الأمراض الفطرية والحشرية).
     - 🧪 فحص وتحليل التربة (تقييم الخصوبة وبرنامج التسميد).
     - 🌾 توصيات المحاصيل (المحاصيل الأكثر ملاءمة وربحية).
     - 💰 أسعار السوق (السجلات المخزّنة).
     - 💧 جدولة الري الذكي (ترشيد المياه).
   - بطاقة الوصول السريع للمستشار الزراعي الذكي.
   - تنبيهات عاجلة: تظهر حالة فارغة صريحة (لا تُختلق أي تنبيهات).

2. **الخدمات (Services):**
   - دليل شامل ومصنف لكافة خدمات منصة AgroGrowth:
     - **التربة والمحاصيل:** تحليل التربة، مقارنة التربة المثالية، اقتراح المحاصيل، الدورة الزراعية.
     - **صحة النبات والوقاية:** كاشف أمراض النبات بالصورة، مكافحة الآفات، جداول الرش.
     - **الري والمناخ:** الري الذكي، الطقس الزراعي، تحليلات توفير المياه.
     - **إدارة المزرعة والمالية:** تسجيل الحقول، متابعة الثروة الحيوانية، تتبع المصروفات.
     - **المجتمع والاستشارات:** استشارة الخبراء الزراعيين والبياطرة، منتدى الفلاحين.

3. **المساعد الذكي (AI Assistant):**
   - مستشار زراعي تفاعلي يفهم اللهجة التونسية والعربية الفصحى والفرنسية والإنجليزية.
   - أزرار اقتراحات سريعة لأسئلة شائعة (ري الزيتون، أمراض الطماطم، تسميد القمح، أسعار السوق).
   - مدعوم بقاعدة المعرفة الزراعية التونسية ونماذج الرؤية الحاسوبية.

4. **السوق والأسعار (Marketplace):**
   - أسعار الجملة المسجّلة في قاعدة بيانات المنصة (بالدينار التونسي د.ت / كغ).
   - عرض موقع السوق وتصنيف الجودة عند توفّرهما في السجل.
   - لا تُعرض أي اتجاهات (ارتفاع/انخفاض) أو نسب تغيّر إلا إذا وفّرها الخادم فعلياً — الأسعار الحالية سجلات غير متحقق منها ويُعلن ذلك بوضوح.

5. **الملف الشخصي (Profile):**
   - بطاقة بيانات الفلاح ومزرعته.
   - **مبدّل تفضيل الدور (Role Preference):** تفضيل محلي يضبط الواجهة وترتيب الاختصارات فقط؛ الدور الفعلي للحساب يُحدَّد من الخادم ولا يُغيَّر من التطبيق.
   - مبدل لغات فوري (العربية، Français, English).
   - أداة تشخيص الاتصال بالخادم وقاعدة بيانات Supabase.

### تدفّق التربة ← المحصول ← المشروع الزراعي (مُتحقَّق منه)

مسار عمل مترابط يعيد استخدام البنية الخلفية القائمة دون أي نقطة نهاية جديدة:

1. **تحليل التربة** (`SoilAnalysisScreen`): اختيار/إنشاء مزرعة وقطعة، ثم إدخال
   القياسات. المسار المفضّل هو `POST /api/soil-analysis/analyze` (استشارة
   مولّدة بواسطة LLM فوق قياسات يدخلها المستخدم غير متحقق منها، وتُحفظ للقطعة).
   عند عدم تهيئة المزوّد (503) يسقط التطبيق إلى المحرك الإرشادي الحتمي
   (`POST /api/soil-analysis/analyze`/المحرك قواعد) ويعلن ذلك — دون تلفيق.
2. **توصيات المحاصيل** (`CropRecommendationScreen`): مساران صادقان:
   - مسار القطعة `POST /api/ai-recommendations`: يقيّم التحليل **المحفوظ** للقطعة؛
     وإن لم يوجد يعيد الخادم 409 `PERSISTED_SOIL_DATA_REQUIRED` ويعرض التطبيق
     حالة صريحة «يلزم تحليل تربة محفوظ» بدل تلفيق نتيجة.
   - مسار القياسات `POST /api/ai/crop-recommendation`: محرك قواعد فوق جدول مرجعي،
     موسوم `rule-based`.
3. **المشروع الزراعي** (`CultivationProjectScreen`): تأكيد المحصول/المزرعة/القطعة
   ثم الحفظ عبر `POST /api/assistant/actions/cultivations` (يتحقّق الخادم من
   الملكية والمساحة والتاريخ). تُبنى قائمة المهام من تقرير التربة **المحفوظ**
   للقطعة (أو متتالية عامة موسومة صراحةً عند غياب تقرير)، وتُحفظ علامات الإنجاز
   محلياً على الجهاز فقط. يُعرض أيضاً قسم «منتجات مطابقة» من
   `GET /api/marketplace/listings` بحالة «غير متاح» صريحة (503) حتى ربط السوق.

> **اختبار حيّ اختياري:** `npm run test:live` (أي `LIVE_API_TESTS=1`) يشغّل
> `tests/live/production-smoke.test.ts` مقابل البوابة الإنتاجية الفعلية باستخدام
> كود العميل نفسه (لا محاكاة)، ليتحقّق من عنوان القاعدة، وترويسة المصادقة، وتخطيط
> مصدر البيانات. يبقى `npm test` دون شبكة ويُتخطّى هذا الاختبار تلقائياً.

### بناء الإنتاج (EAS)

ملف `eas.json` يضبط ملفات البناء للإنتاج ويشير صراحةً إلى البوابة الإنتاجية:

- `development`: عميل تطوير داخلي (APK) — يتصل بالبوابة المنشورة.
- `preview`: APK داخلي للاختبار السريع.
- `production`: AAB (Google Play) مع `autoIncrement` للنسخة.

```bash
npx eas build --profile preview     # APK للتجربة على جهاز حقيقي
npx eas build --profile production  # حزمة AAB للإصدار
npx eas submit --profile production # الرفع إلى المتجر
```

جميع الملفات تُبنى بـ `EXPO_PUBLIC_API_BASE_URL=https://agrodev-3.onrender.com`
مضبوطاً في `eas.json`، فلا يعتمد الإصدار على أي قيمة محلية.

### الوصول والوصولية (Mobile-First)

- كل عنصر تفاعلي أساسي يبلغ هدف لمسٍ ≥ 48dp (الأزرار `sm`/`md`/`lg`، الشرائح،
  أيقونات الرأس، تبويبات التنقل السفلية) — محميّ باختبار `tests/unit/touch-targets.test.tsx`.
- كل نمط نصي يحمل `fontSize` مصحوباً بـ `lineHeight` (≈1.5×) لقراءة عربية مريحة،
  بما في ذلك النصوص الثانوية والتسميات.
- الواجهة عربية أولاً مع دعم RTL كامل وتبديل فوري للفرنسية والإنجليزية (تحقّق
  تكافؤ المفاتيح: 125 مفتاحاً رئيسياً + 395 مفتاحاً إضافياً + 226 مفتاحاً
  لتدفّق التربة × 3 لغات، 0 مفقود — محميّ باختبارات `i18n.test.ts` و
  `soil-detail.test.ts`).

### الخدمات المتكاملة فعلياً (مع مصدر البيانات المُعلَن)

| الميزة | نقطة النهاية | مصدر البيانات المُعلَن |
| --- | --- | --- |
| الطقس | `GET /api/weather/coordinates` | رصد حي (Open-Meteo) — `isRealData: true` |
| تحليل التربة | `POST /api/ai/soil-analysis` | محرك قواعد — `rule-based` |
| توصيات المحاصيل | `POST /api/ai/crop-recommendation` | محرك قواعد — `rule-based` |
| تشخيص أمراض النبات | `POST /api/ai/images/detect-disease` | نموذج رؤية (يفشل بأمان 503 إن لم يُهيّأ) |
| مكافحة الآفات | `POST /api/pest-control/identify-from-symptoms` | مطابقة كلمات مفتاحية — `rule-based` |
| الري الذكي | `POST /api/irrigation-optimization/water-requirements` | خدمة مصغّرة (تفشل بأمان 503 إن لم تُشغَّل). تُرسل درجة الحرارة والرطوبة من الطقس الحي (Open-Meteo) لولاية المستخدم؛ وعند تعذّر الطقس تُحذف الحقول ولا تُختلق قيم — ويُعلَن ذلك في الواجهة. |
| أسعار السوق | `GET /api/market/all` | سجلات المنصة غير متحقق منها — `isRealData: false` |
| المستشار الذكي | `POST /api/ai/assistant/chat` | LLM إن كان مُهيّأً، وإلا قواعد (`rule-based`) |
| الإشعارات | `GET/PATCH /api/notifications` | Supabase — `isRealData: true` (تتطلّب جلسة مُتحقَّق منها) |
| الثروة الحيوانية | `GET /api/animals` | Supabase — `isRealData: true` (تتطلّب جلسة مُتحقَّق منها) |
| الحقول والمزارع | `GET/POST /api/farms`, `/api/fields` | Supabase (تتطلّب دور `farmer`) |
| قدرات الذكاء الاصطناعي | `GET /api/ai/capabilities` | مصدر الحقيقة المُعلَن من الخادم |

### ميزات معروضة بحالة صريحة (غير مُفعّلة على الخادم)

- **منتدى المجتمع والاستشارات** (`/api/collaboration/*`): موجودة على الخادم لكنها
  معطّلة (503، بيانات في الذاكرة غير مثبّتة). يعرض التطبيق حالة «غير متاح» ولا
  يختلق أي منشورات.
- **تنبيهات الصفحة الرئيسية**: تُعرض حالة فارغة صريحة.
- **الري الذكي / تشخيص الصور**: عند عدم تشغيل الخدمة المصغّرة أو عدم تهيئة نموذج
  الرؤية، يعرض التطبيق حالة «غير مُهيّأ» بدل أي نتيجة مُختلقة.

### متغيّرات البيئة المطلوبة

انسخ `.env.example` إلى `.env` واضبط (جميع القيم عامة، تبدأ بـ `EXPO_PUBLIC_`).
جميعها اختيارية: للتطبيق قيم افتراضية صالحة للإنتاج.

- `EXPO_PUBLIC_API_BASE_URL`: عنوان بوابة Express. الافتراضي في بناء الإنتاج هو
  `https://agrodev-3.onrender.com`؛ وفي التطوير `http://localhost:5000`
  (ولمحاكي أندرويد `http://10.0.2.2:5000`). اضبطه فقط لتجاوز الافتراضي (مثلاً جهاز
  حقيقي يشير لعنوان IP محلي).
- `EXPO_PUBLIC_SUPABASE_URL` و `EXPO_PUBLIC_SUPABASE_ANON_KEY`: مشروع Supabase
  (المفتاح عام ومحمي بـ RLS). القيم الافتراضية تشير لمشروع تطبيق الويب نفسه
  (`https://jymrhhlwdbclctobhbsi.supabase.co`).
- `EXPO_PUBLIC_API_TIMEOUT_MS` (افتراضي 15000)، `EXPO_PUBLIC_CACHE_TTL_MS`
  (افتراضي 21600000)، `EXPO_PUBLIC_IMAGE_MAX_EDGE` (افتراضي 1280)،
  `EXPO_PUBLIC_IMAGE_QUALITY` (افتراضي 0.75).

**لا تضع أبداً** مفتاح `service_role` أو مفتاح مزوّد ذكاء اصطناعي أو `DATABASE_URL`
داخل هذا التطبيق؛ فالتطبيق يتحدّث إلى الخدمات الذكية حصراً عبر بوابة Express التي
تحتفظ بالأسرار على الخادم. كل عناوين الخدمات المصغّرة (Soil/Crop/Image/…) تبقى
**على الخادم فقط** ولا تُضاف إلى تطبيق الجوال.
